built with Python, FastAPI, ChromaDB, and a local Ollama LLM.

> **Learning Goal:** Understand every piece of the pipeline — not just make it work.

## 1. Project Purpose

This project lets you:

- **Ingest** documents (PDF, TXT, DOCX, CSV, XLSX, images) into a local vector database.
- **Query** those documents using natural language.
- **Get answers** generated by a small local LLM (via Ollama) that cites which documents it used.

The emphasis is on **simplicity and transparency** — you should be able to trace
any answer back through the pipeline step by step.

## 2. Architecture

```
Documents (PDF / TXT / DOCX / CSV / XLSX / Images)
      │
      ▼
 Ingestion Service          ← detects file type, calls the right parser
      │
      ▼
 Parsers                    ← PyMuPDF, python-docx, pandas, pytesseract
      │
      ▼
 Normalized Document Dict   ← { text, source, page, file_type, bucket }
      │
      ▼
 Chunking Service           ← splits long text into smaller overlapping pieces
      │
      ▼
 Embedding Service          ← sentence-transformers → float vector per chunk
      │
      ▼
 ChromaDB                   ← stores vectors + metadata on disk
      │
      ▼
 ─────────────────── QUERY TIME ───────────────────────────────────────────
      │
 Question (from API)
      │
      ▼
 Embed the question
      │
      ▼
 ChromaDB similarity search (filtered by bucket)
      │
      ▼
 Vector candidates (top_k x 2)
      │
      ▼
 Local CrossEncoder reranking
      │
      ▼
 Top-K relevant chunks
      │
      ▼
 Build prompt = system prompt + context chunks + question
      │
      ▼
 Ollama (local LLM)
      │
      ▼
 Answer + source citations
      │
      ▼
 FastAPI JSON response       ← tested via Postman
```

### Two Buckets

```
data/
├── bucket_1/   ← ~50 documents (e.g. HR policies)
└── bucket_2/   ← ~50 documents (e.g. technical manuals)
```

Both buckets share **one ChromaDB collection**. Each chunk is tagged with its
bucket in metadata. At query time you specify `"bucket": "bucket_1"` and only
that bucket's chunks are searched.

## 4. Installation

### Prerequisites

- Python 3.10 or higher
- [Ollama](https://ollama.com/download) installed and running
- (Optional) [Tesseract OCR](https://github.com/UB-Mannheim/tesseract/wiki) for image parsing

### Steps

```bash
# 1. Navigate to the project folder
cd rag_project

# 2. Create and activate a virtual environment
python -m venv .venv
.venv\Scripts\activate          # Windows
# source .venv/bin/activate     # Mac/Linux

# 3. Install dependencies
pip install -r requirements.txt

# 4. Set up your environment file
copy .env.example .env          # Windows
# cp .env.example .env          # Mac/Linux

# 5. Edit .env if needed (e.g., change OLLAMA_MODEL)
```

## 5. Ollama Setup

Ollama runs a local LLM server. You interact with it just like an API.

```bash
# 1. Download and install Ollama from https://ollama.com/download

# 2. Pull the configured answer model
ollama pull qwen2.5:7b

# Other small options:
# ollama pull llama3.2       (~2 GB)
# ollama pull gemma2:2b      (~1.6 GB)
# ollama pull mistral        (~4 GB)

# 3. Verify it works
ollama run qwen2.5:7b
# Type: "Hello, what is RAG?" and press Enter. Type /bye to exit.

# 4. The Ollama server must be running when you use the RAG API.
#    It starts automatically on most systems, or run: ollama serve
```

To change the model, edit `OLLAMA_MODEL` in your `.env` file.
**You don't need to change any Python code.**

## 7. How to Ingest Documents

Place your documents in the appropriate bucket folder:

```
data/bucket_1/employee_policy.pdf
data/bucket_1/onboarding_guide.docx
data/bucket_2/technical_manual.pdf
```

Then call the ingest endpoint:

```bash
# Ingest all files in bucket_1
POST http://localhost:8000/ingest
{
    "bucket": "bucket_1"
}

# Ingest a single specific file
POST http://localhost:8000/ingest
{
    "file_path": "data/bucket_1/employee_policy.pdf",
    "bucket": "bucket_1"
}
```

Re-indexing is incremental. Unchanged files are identified by SHA-256 fingerprint
and skipped before parsing, chunking, embedding, and storage. New or changed files
are processed. Changed files replace their old chunks, and removed files are
removed from the bucket index.

## 8. How to Query

```bash
POST http://localhost:8000/query
Content-Type: application/json

{
    "question": "What is the annual leave policy?",
    "bucket": "bucket_1"
}
```

Response:

```json
{
    "answer": "Employees are entitled to 20 days of annual leave...",
    "sources": [
        { "document": "employee_policy.pdf", "page": 4 },
        { "document": "onboarding_guide.docx", "page": null }
    ]
}
```

## 10. Postman Testing

1. Open Postman
2. Create a new collection called **RAG Project**
3. Add these requests:

**Health Check**
- Method: `GET`
- URL: `http://localhost:8000/health`

**Ingest Bucket**
- Method: `POST`
- URL: `http://localhost:8000/ingest`
- Body (JSON): `{ "bucket": "bucket_1" }`

**Query**
- Method: `POST`
- URL: `http://localhost:8000/query`
- Body (JSON): `{ "question": "...", "bucket": "bucket_1" }`

**Debug Retrieval (no LLM)**
- Method: `POST`
- URL: `http://localhost:8000/retrieve`
- Body (JSON): `{ "question": "...", "bucket": "bucket_1" }`
- This returns the raw chunks WITHOUT calling Ollama — great for debugging.

## 11. Bucket Behaviour

- Both buckets live in the **same** ChromaDB collection.
- Every chunk is tagged: `{ "bucket": "bucket_1" }` or `{ "bucket": "bucket_2" }`.
- When querying, specify `"bucket"` in the request body.
- The retriever uses ChromaDB's `where` filter: `{"bucket": "bucket_1"}`.
- This means a question about bucket_1 will **never** retrieve chunks from bucket_2.
- If you omit `"bucket"`, the system searches across all documents.

## 13. Troubleshooting

### `ModuleNotFoundError: No module named 'fitz'`
```bash
pip install pymupdf
```

### `TesseractNotFoundError`
Tesseract is not installed. Download from:
https://github.com/UB-Mannheim/tesseract/wiki

After installing, if it's still not found, add this line to `image_parser.py`:
```python
pytesseract.pytesseract.tesseract_cmd = r"C:\Program Files\Tesseract-OCR\tesseract.exe"
```

### `Connection refused` when querying Ollama
Make sure Ollama is running:
```bash
ollama serve
```
Or check: http://localhost:11434

### `model not found` error from Ollama
Pull the model first:
```bash
ollama pull qwen2.5:7b
```

### PDF extracted no text
The PDF is likely scanned (image-based). You need to run it through the image OCR
pipeline. Use a tool like `pdf2image` to convert PDF pages to images first,
then pass them through `image_parser.py`.

### ChromaDB errors
Delete the `vectorstore/` directory and re-ingest:
```bash
rm -rf vectorstore/
python tests/test_ingestion.py  # or use the /ingest API
```

### Empty answer from LLM
1. Check `/retrieve` first — were relevant chunks found?
2. If no chunks returned, the document may not have been ingested.
3. If chunks found but answer is poor, try a larger model or adjust RETRIEVAL_TOP_K.

### `MIME type mismatch`
Uploaded files must report a MIME type compatible with their supported extension.
Obvious mismatches are rejected before the file is saved or parsed.

### `Logging`
Application logs appear in the terminal and are also written to `logs/app.log`.
The `logs/` directory is created automatically when the application starts.
